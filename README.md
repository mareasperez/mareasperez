## 🧠 How I Approach Software Engineering

Over time, I've developed a few principles that guide how I work.

**Understand the problem before writing the solution.**

A technically correct implementation can still be the wrong solution if it ignores the surrounding system.

**Think beyond the happy path.**

Timeouts, unexpected responses, partial failures, retries, and inconsistent data are not unusual edge cases in production. They're part of building reliable software.

**Tests are part of the design process.**

I increasingly follow a **Red → Green → Refactor** workflow, using tests to define expected behavior before implementing changes.

**Respect legacy systems, but don't be afraid to improve them.**

Older applications often support critical operations. Modernization should be deliberate, incremental, and supported by appropriate testing.

**Use AI as an engineering tool, not a substitute for engineering judgment.**

I use AI to accelerate development, explore alternatives, and improve test coverage, while keeping architectural decisions, correctness, and production impact at the center of the process.
